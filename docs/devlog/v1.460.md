## v1.460 — The room list, and its matchmaker
Card `fable/d2-room-list`, its second and last step: backlog D.2 step 3. Michael chose on 14 Oct to start online play on PeerJS's free public matchmaker, knowing it can't list rooms, and on 28 Oct (**B**) asked for the room list on "a small matchmaker you set up (a free server account; a local session helps you set it up)". A cloud session can't make his account or deploy to it, so this version builds the matchmaker and the game's side of the list, tests both here, and leaves him the steps below. Until he pastes the address in, the game behaves as before: rooms are joined by their code.

**The matchmaker** (`server/matchmaker/`, not shipped to players: itch gets only index.html and js/). A Cloudflare Worker on the free plan, with one Durable Object, `Lobby`, holding the list in memory so everyone sees the same one wherever they are. Its rules are in `rooms.mjs`, plain JavaScript with no Cloudflare in it, so the game's suite runs the very same code: a room is its four-letter code, the host's name, the map, the mode, the size, the people in and the most that fit, day or night, and the game's version. Each field is cleaned to what the game itself would send (the code in the game's own letters, names in the game's own characters), a host's first word carries a random key and only that key can change or remove the room, a room with no word for 45 s is gone, and the list holds at most 300 rooms and returns the newest 50. `worker.mjs` answers GET /rooms, POST /rooms and DELETE /rooms/<code>, open to every origin (the game runs from itch's page or from a downloaded file). The README says how to deploy it and what it costs: nothing (100,000 requests a day free; a listed room is 240 an hour, an open online screen 360; past the allowance Cloudflare refuses rather than bills, and the game falls back to codes).

**The one setting.** `NET_MATCHMAKER_URL` at the top of the online code in `js/94-pickup-online.js`, empty. Nothing reads it until someone opens the online screen, so the game fetches nothing at startup either way.

**What a player sees, with no address (today).** The online screen (from the title's ONLINE or the board's PLAY ONLINE) has a new **Open rooms** row: "Rooms are joined by their code: the host reads it out to you." Everything else is as before.

**With an address.** Open rooms lists every room whose host chose Listed, newest first, one a line: "Hosty’s room · 2v2 on Winnmark Court · 1/6" and a **JOIN**, which does exactly what typing the code and pressing JOIN does. It refreshes every 10 s while the screen is up, and only that line is redrawn, so a code half typed in JOIN's box stays put. "No open rooms right now. Host one, or join by a code." when there are none; a room from another version of the game says so and can't be joined (the host would turn it away); a full one reads FULL. If the matchmaker can't be reached: "Couldn’t reach the room list. Join by the code instead.", and the codes work as ever.

The host's room has a new row, **Who sees it: Private / Listed**, Private to start with every room (the card: a public room is the host's choice, since players see each other's internet addresses). Listed sends the room's word at once and every 15 s, so the list's count of people stays right; the note beside it reads "on the room list", or "the room list is down: friends join by the code". The room comes off the list at once when the host sets Private, leaves the room or closes the tab, and while its match is on (it is back when REMATCH brings them to the room); a host whose game vanished drops off 45 s after his last word. The privacy line under the screen adds, with an address set: "A Listed room’s name and match show on the room list to anyone who opens it, and anyone can join it from there."

Under it: one timer (`netMmTick`, once a second) runs only while it has work, the online screen up or a listed room open, and stops itself after. `netMmFetch` is the one place the game talks to the matchmaker, and counts its calls (`Net.mm.fetches`) for the suite.
