## v1.462 — Recorded voices, step 2: the clip player
Card `fable/d9-recorded-voices`, backlog D.9, its second step (v1.461 gave every line an id and wrote the script). This
is what plays a recorded line once there are some. With none, which is how it ships, the game sounds exactly as before.

**Where the clips live.** `js/28-voice-clips.js`, a new file in the play lane, holds `VOICE_CLIPS`: one entry a clip,
named as docs/voice_script.md names it (`seth.taunt.3`, `seth.teammate.4`), with the line's words when it was
recorded, its length and the audio as base64 text. Only `scripts/voicepack.mjs` (step 3) writes it. It is a classic
script beside the others, because the game ships as index.html and the js/ files and must still open from a
double-clicked download, where nothing may be fetched; and itch is sent `js/*.js` only. It ships empty (a 0.6 KB
file). The audio is decoded the first time its line is said and kept, never at startup, so a pack costs the browser
only the text it reads while the page loads (step 3 puts a cap on that).

**What plays.** Every place a kid speaks now asks for his clip of the line first (`voiceClipFind`): `tryNpcSpeak` (every
situation in a match), its walkie branch, an order's answer on the walkie (`squadWalkieSay`), the noodle and the crew
in your room (`kidSayLine`). A clip is used only when it is this kid's reading of this line (his own line, or a shared
line under his name) and the words it was recorded with are still the line's: a line edited after recording falls back
to the browser voice rather than playing the old take. Then (`voiceClipPlay`):
- **Near:** through the effects bus, panned from where he stands and as loud as the browser voice would be at that
  distance (`VOICE_CLIP_GAIN` 0.6 × the same distance curve). No chirp first: the chirp was there because the browser
  voice can't be panned, and the clip is.
- **Over the walkie:** band-limited (350 Hz to 3 kHz) under the same click and static as v1.386, the static now running
  the clip's own length instead of a guess from the words.
- Either voice cuts the other off, as the browser voice always cut itself off; the end of a round stops a clip as it
  cancels speech.
- **A clip that won't decode** (a bad file, an Ogg on an old Safari): the browser voice says the line that once, and
  that clip is not tried again this visit.
- Everything around the sound is untouched: the earshot cut-off, the cooldowns (1.5 s after anyone, 4 s after
  himself), the walkie's spacing, the no-repeat memory and `VOICE.log` all run before the voice is chosen.

Under it: `VOICE_CLIP` (the log, the decoded buffers, the failures), `voiceClipFind`, `voiceClipPlay`, `voiceClipStop`,
`voiceSpeechCancel` and `npcTts` (the browser-voice half of `tryNpcSpeak`, moved out unchanged so a clip can fall back
to it) in 20-characters; `kidSayLine` (14-gear) and `walkieVoice`/`squadWalkieSay` (76-bbs) take the line's id or clip;
`endScenario` (64-scenario-flow, core) stops a clip. CLAUDE.md's file count, lanes and code map name the new file.
